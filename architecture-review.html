Solution: pull launch behavior behind one seam and justify it with two adapters: Windows in production, test adapter in verification.
Benefits: locality improves because launch quirks stop leaking into update logic; leverage improves because one launch interface covers every alias function.

Problem: install flow is understandable now, but the interface is starting to mirror the implementation, especially when profile mutation and dependency recovery grow.
Solution: if install behavior expands, deepen it as one workflow module instead of adding more helper splits around profile content and repository trust.
Benefits: locality improves for bootstrap failures; leverage improves because install and uninstall policy live in one place.
